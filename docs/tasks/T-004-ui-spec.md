- 브랜치: `exec5/T-004-ui-spec`

## 목표

지금의 tkinter 화면들이 제공하는 것을 빠짐없이 목록으로 만들고, 각 항목이 엔진의 어떤
명령/이벤트에 대응해야 하는지 적는다. 이 문서는 (1) D1 결정 뒤 WP-D 구현의 명세이고
(2) T-002 (실행1) 이벤트 설계의 입력이다. UI 툴킷은 가정하지 않는다.

## 소유 경로

- `docs/ui-spec.md` 하나. 코드 변경 없음.

## 내용

근거: `scripts/launcher.py`, `scripts/live_focus.py` (912줄; `XYMap`, `Trace`, `Gauge`, `Sample`,
`main` 안의 키 핸들러), `docs/runs/2026-09-30_substrate-scan.md` 2절 (절차와 운영 규칙),
`docs/PLAN.md` 4·5·6절.

1. **화면 목록**: 런처, 라이브 뷰(전체 프레임 + ROI 표시), 초점 게이지, 지표 트레이스,
   XY 지도(경계점, 방문 필드, 원 피팅), 샘플 패널, 상태 표시. 각 화면이 보여 주는 값과 갱신 주기.
2. **입력 목록**: 키 바인딩 전부 (`t` 추적, `+`/`-` 속도, `Esc` 중지, 저장, 경계 표시/되돌리기,
   박스 토글, 서보, 스윕, 다음 샘플, tare 등 — 코드에서 확인해 적는다), 명령행 인자
   (`--set`, `--aura`, `--sample`, `--hole-diameter`, `--record` …), 마우스 조작.
3. **확인 대화상자**가 필요한 지점: 100x 상향 재중심 승인, 오일 확인 대기, 소프트웨어 렌즈 회전
   승인, 샘플 전환. 대화상자는 추가 확인일 뿐 가드를 대신하지 않는다 (PLAN.md 4절).
4. **엔진 대응표**: 항목마다 → 명령(이름, 인자) / 이벤트(이름, 필드). 이것이 T-002 `events.py`
   의 입력이다. 현재 코드가 UI 안에서 직접 하는 하드웨어 호출(조명 `--set`, 추적 중 XY 이동,
   서보 Z 이동)은 모두 엔진 명령으로 옮겨 적는다.
5. **운영 규칙의 화면 강제**: 명시야로 가장자리 추적 후 입자 조명으로 전환, 세션마다 재추적
   (오래된 hole 피팅 재사용 금지, 1.5 mm 이동 사례), 100x 스윕을 4x 초점에 중심 두지 않기,
   종료 시 소등 상태 표시, 모델 판정은 `in_focus | step_up | step_down | no_sample_here | unsure`
   어휘로만 표시하고 Z 숫자는 엔코더 값만 보여 주기.
6. **M1 범위 표시**: 각 항목에 M1 (샘플 선택, 라이브 뷰, 상태, 소등) / M3 / M4 를 붙인다.

문서는 한국어, UI 문구는 영어로 인용한다 (PLAN.md 머리말). 표를 적극 쓴다.
